Manter este manual

Documentação divergente é pior do que documentação ausente: ela custa a mesma leitura e devolve uma resposta errada com a mesma confiança. Esta página diz qual arquivo tocar para cada tipo de mudança, e qual é o checklist antes de fechar uma feature.

A regra

Uma feature não está pronta enquanto a documentação não reflete o que ela fez. Isso está em CLAUDE.md como regra do repositório, não como sugestão. Se a mudança alterou comportamento, contrato, configuração, esquema ou uma decisão registrada, ela alterou este manual.

Quem documenta o quê

ArquivoRespondeRegistro
CLAUDE.md O que é permitido escrever. Regras não negociáveis, curtas e imperativas Normativo
docs/frontend-standards.md Como o frontend deve evoluir. Catálogo de componentes, regras de token, i18n, dados Normativo
backend/README.md O racional longo do backend. A argumentação completa por trás de cada mecanismo Narrativo
docs/manual/ (aqui) Como o sistema funciona hoje. Mecanismo, fluxos, referência operacional, matriz de testes, registro de decisões Descritivo
README.md, docs/deployment.md Como rodar e publicar Instrucional
brand-identity.md e afins Identidade de marca — ainda não a linguagem visual do app Referência de marca

A distinção que evita duplicação: CLAUDE.md manda, este manual explica. Uma regra nova entra em CLAUDE.md em uma ou duas frases; o mecanismo, o diagrama e a consequência entram aqui. Nunca copie a regra inteira para os dois lugares — copie o link.

O que atualizar, por tipo de mudança

Você mudou…Atualize
Entidade, coluna, migration, chave, coluna JSON Modelo e banco (tabela de tabelas, de migrations, e os nulls se aplicável) + o diagrama ER
Endpoint novo, rota, status code, header, precondição Contrato HTTP + VaultApi no frontend + ContractTests
Regra de autenticação, papel, filtro, throttle Tenancy e segurança (incluindo a lista de rotas anônimas) + matriz de testes
Qualquer coisa em imagens: variante, derivação, focal, coletor Imagens e coletor + referência de configuração
Página, rota do SPA, componente ui-*, store, util puro App Angular e docs/frontend-standards.md (o catálogo é normativo lá)
Chave de configuração, variável de ambiente, volume, passo de CI Deploy e suporte + docs/deployment.md
Um caminho ponta a ponta (login, save, upload, import…) Fluxos ponta a ponta
Teste novo que prende uma invariante Testes e garantias — a matriz, não a contagem
Um trade-off deliberado, de qualquer natureza Decisões técnicas: um ADR novo, com o próximo número livre. Nunca renumere os existentes
Uma limitação conhecida apareceu ou foi resolvida Visão geral → limites + lacunas
Um sintoma novo que suporte vai receber Sintomas e causas

Checklist para colar no PR

## Documentação
- [ ] CLAUDE.md: regra nova ou alterada? (imperativa, 1–2 frases)
- [ ] docs/manual/: página(s) afetada(s) atualizada(s)
- [ ] docs/manual/decisions.html: ADR novo para cada trade-off deliberado
- [ ] docs/manual/testing.html: matriz atualizada se um teste prende algo novo
- [ ] docs/manual/operations.html: chave de config, volume ou sintoma novo
- [ ] Diagrama afetado redesenhado (ou removido, se virou mentira)
- [ ] Nenhuma afirmação aspiracional: só o que o código faz hoje

Convenções deste manual

  • Descreva o que existe, nunca o que deveria existir. Se um comportamento está pela metade, diga isso e marque com um callout — como o aviso sobre Section em Modelo e banco. Uma feature incompleta documentada como pronta é pior do que não documentada.
  • Prosa em pt-BR; identificadores em inglês. Nomes de arquivo, classes, chaves de configuração, headers HTTP e trechos de código ficam como estão no código. Não traduza If-Match, ETag, ImageGc:GracePeriod nem nomes de teste.
  • Diga a consequência, não só o mecanismo. “Existe um interceptor” não ajuda ninguém. “Sem o bump, um PUT desatualizado desfaz a edição de outra pessoa em silêncio” ajuda.
  • Todo diagrama usa os tokens de tema (classes .box, .t, .ln em assets/manual.css), nunca cores fixas — o manual tem tema claro e escuro. Todo <svg> carrega <title> e, quando o conteúdo não é óbvio, <desc>.
  • Tabela larga vive dentro de .table-wrap, que rola horizontalmente. O corpo da página nunca rola na horizontal.
  • Nada de dependência externa. O manual abre direto do disco (file://): sem CDN, sem fonte remota, sem fetch.

Adicionar uma página

  1. Copie o esqueleto de qualquer página existente e troque data-page no <body> por um id novo.
  2. Adicione uma entrada em PAGES no topo de assets/manual.js. É a única lista: a barra lateral, a numeração e os links anterior/próxima de todas as páginas saem dela.
  3. Adicione um card em Visão geral → mapa do manual.
  4. Dê id a cada <h2>: o script transforma em âncora clicável, e outras páginas linkam para seções.

Revisão periódica

Duas verificações que valem uma passada trimestral, ou depois de qualquer release grande:

  1. Os caminhos ainda existem? Toda referência a arquivo neste manual é caminho/relativo.ts. Um grep pelos nomes citados encontra os que sumiram. Foi assim que a divergência do ExportApi/ArchiveApi apareceu
  2. Os padrões ainda batem? Compare a tabela de configuração de Deploy e suporte com backend/src/Vault.Api/appsettings.json. Um padrão errado num manual de operação é a forma mais cara de erro que este documento pode conter.

Divergências registradas

Quando você encontra uma divergência e não pode corrigi-la na hora, registre-a em vez de deixar quieto. Um leitor avisado perde minutos; um leitor não avisado toma a decisão errada.
