O app Angular

Angular 21, TypeScript estrito, zoneless, signals, OnPush em todo lugar. Quatro regras carregam o peso: tokens de design apenas, a biblioteca ui-* como fonte única de elementos, a URL como estado, e nenhuma string visível dentro de componente. As regras normativas completas estão em docs/frontend-standards.md; aqui está como o código está organizado hoje.

Versões nunca saem de dentro de Collection

VaultStore guarda o mapa de versões, e HttpVaultApi lê versão do envelope da listagem e do header ETag. Se algum dia a versão passar a ser um campo de Collection, ela entra no arquivo de backup — e o Collection é literalmente o formato do arquivo.

Não “otimize” os pipes para puros

Um pipe puro é memoizado pelos argumentos: quando o idioma muda, transform recebe a mesma chave e o Angular devolve a string cacheada, congelando todo rótulo da tela no idioma antigo. A versão impura custa uma busca em dicionário em views que já estavam sendo verificadas.

URL como estado

Qualquer coisa que o usuário gostaria de ver restaurada num refresh, num voltar ou num link compartilhado vive na rota. Duas regras mantêm isso honesto:

  1. Query string é entrada não confiável, parseada em features/collection/browse-params.ts — condição desconhecida ou chave de ordenação não declarada lê como “sem filtro”, nunca como “filtra tudo fora”.
  2. A lista vem só de browse.util.ts. A grade e a página do item consumirem uma função é o que impede as duas de discordarem sobre quem vem a seguir.

Links que abrem um grupo passam por groupLinkParams: mescla mantém filtros e visualização, e a ordenação ad-hoc é descartada de propósito — cada grupo declara a sua, e uma escolha pontual não tem por que sobreviver ao grupo em que foi feita. A seção (?s=) é descartada junto, por um motivo mais forte: ela pertence a exatamente um grupo, então levá-la para outro nomearia um separador que aquele grupo não tem e esvaziaria a tela. Filtros e ordenação navegam com replaceUrl.

Seções: ordenam, não escopam

Uma seção é um separador dentro da lista de um grupo (o modelo está em Seções). O que a mantém barata no frontend é uma escolha só: ela é uma chave de ordenação, não um escopo. scopeItems, subtreeIds, o breadcrumb e a árvore de grupos não sabem que ela existe.

  1. sortItems recebe o rank das seções do grupo aberto e usa como chave primária; a ordenação escolhida só desempata dentro de cada faixa. Um separador cujos itens se intercalam com os da faixa seguinte não é um separador. A direção do sort inverte os itens de cada faixa, nunca as faixas — essa ordem o usuário arrumou à mão.
  2. chunkBySection só corta a lista já ordenada em faixas para renderizar. Cada entrada carrega o índice dela na lista, não na faixa, então arrastar e os botões de mover continuam trabalhando em coordenadas de lista.

A consequência é que as setas ← → da página do item continuam corretas sem uma linha de código novo: elas andam pela mesma lista plana, na mesma ordem que a grade mostrou. O rank vem de sectionRank, que só conhece as seções do grupo aberto — é assim que um item apontando para a seção de outro grupo cai na faixa “sem seção” de graça, sem nenhuma checagem explícita.

?s= é um filtro, ao lado de ?cond= e ?own=, e não um destino: o cabeçalho da faixa é um <button> com aria-pressed, que alterna. Arrastar um item por cima de um cabeçalho é como ele muda de seção — a seção de destino é lida do item que ele deslocou, porque um slot pertence sem ambiguidade a quem estava nele.

Idioma

O app ship em pt-BR e en, trocáveis em runtime. Português é o idioma-fonte da marca. en.ts declara as chaves (~480 hoje) e pt-BR.ts é Record<MessageKey, string> — tradução faltando ou sobrando é erro de compilação.

RegraDetalhe
Nenhuma string visível em componenteTemplate usa | t; .ts usa I18nService.t. Ambos só aceitam MessageKey, então chave inventada quebra o build
Tabelas de rótulo são computedUm const TABS = […] captura um idioma para sempre
Nunca concatene string traduzidaOrdem de palavras muda entre idiomas: 'Collapse ' + name vira 'groupTree.collapseGroup' | t: { name }
Plural são duas chaves.one / .other via I18nService.plural. Português e inglês concordam em um-vs-resto, então ICU não compraria nada
Maiúscula é CSSDicionário em caixa de frase; text-transform faz o resto — tradutor recebe texto legível

Não são traduzidos, porque são dados: valores de enum na transmissão (Mint/Good/Fair, Keep/ForTrade/ForSale, Owner/Editor/Viewer, text/number/date, free/pro) — eles são simultaneamente a representação SQL e a whitelist do validador do servidor; a tag 'wanted'; nomes próprios (“Vault”, nomes de tema, nomes de plano); e qualquer coisa que o usuário digitou.

Temas e tokens

Um tema é um conjunto de custom properties CSS escopado em [data-theme='<id>'] em styles/_themes.scss. O padrão (Paperwhite) fica em :root. Componentes e páginas nunca escrevem valor visual — cor, fonte, raio, borda ou sombra. Um rebrand inteiro toca um arquivo.

Adicionar um tema: um bloco em _themes.scss, um ThemeDef em core/state/themes.ts, o id em ThemeId e uma chave theme.<id>.description nos dois dicionários. Nada mais. O nome do tema é nome próprio e não é traduzido; a descrição é chave.

Mixins compartilhados em _mixins.scss: panel, mono-label, display-heading, stripes e wanted-photo — o par cinza+fade que toda foto de item não possuído usa, no card, na página do item e na capa.

Acessibilidade

  • <a>/<button> reais para qualquer coisa clicável; :focus-visible visível, definido globalmente.
  • Status nunca só por cor — badges combinam cor e texto, e a barra de progresso imprime os números.
  • Um atalho de seta é adição a um controle real, nunca substituição: o ←/→ da página do item anda entre itens, mas cada passo também é uma âncora com href. O atalho se cala dentro de um campo que precisa do cursor e dentro da faixa de fotos, onde as setas movem fotos.
  • Uma extremidade de sequência renderiza como <span>, e não como link que recebe foco e se recusa a ir a lugar nenhum.
  • Tudo arrastável tem caminho por teclado (ui-reorder, ui-image-focus).

Verificar antes do merge

  1. npm run build limpo — avisos incluídos. O orçamento de 6 kB de estilo por componente é real, e o inicial tem aviso em 500 kB (angular.json).
  2. npm test -- --watch=false verde. Um spec que asserta texto visível tem que fixar o idioma (TestBed.inject(I18nService).apply('en')) em vez de depender do navigator.language do runner.
  3. Os fluxos afetados exercitados no navegador (npm start), em pelo menos um tema escuro — regressões de token quase só aparecem lá — e em português, que roda ~20% mais longo que o inglês e é onde estouro de texto aparece primeiro.
