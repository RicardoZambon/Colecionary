Referência de engenharia e suporte para o Colecionary, que hoje é entregue sob o nome de trabalho Vault — Collection Control: uma API .NET 10 que serve um SPA Angular 21 a partir da mesma imagem Docker, com SQL Server e multi-tenancy imposta pela camada de dados.

O produto, em um parágrafo

O Colecionary cataloga coleções pessoais. Uma coleção tem uma árvore de grupos aninhados e uma lista de itens; cada item é a entrada de catálogo e carrega as cópias físicas que a pessoa possui. Posse não é um campo: um item com pelo menos uma cópia é possuído, um item sem nenhuma está na lista de desejos. Grupos declaram campos personalizados tipados, a ordenação padrão dos seus itens e, opcionalmente, o tamanho declarado do conjunto completo — para que o progresso seja medido contra a série, e não apenas contra o que já foi catalogado. Um Store global publica checklists curados que qualquer conta pode instanciar como coleção nova. Tudo é multi-tenant: um tenant é uma conta/organização, e o isolamento é imposto pelo banco.

Rodar em desenvolvimento

./dev.sh                 # API em :5100 + SPA em :4200, logs prefixados
./dev.sh api             # só o backend
./dev.sh web             # só o frontend

# backend/ — precisa de um SQL Server acessível
docker compose up -d                    # SQL Server 2022 em localhost:1433
dotnet run --project src/Vault.Api      # migra e popula demo em Development
dotnet test                             # unitários + integração (Testcontainers)
dotnet format --verify-no-changes

# frontend/
npm start                # dev server em :4200, espera a API em :5100
npm test -- --watch=false
npm run build            # precisa passar antes de qualquer merge

Conceitos essenciais

Vocabulário que aparece em todas as páginas seguintes, no código e nas mensagens de erro. Vale ler antes de abrir qualquer arquivo.

TermoO que éOnde vive
Tenant A conta/organização. Toda entidade que pertence a um tenant implementa ITenantOwned e é filtrada automaticamente. Identity.Tenants
Coleção Raiz de agregado. Grupos, itens e membros só mudam através dela — não existem endpoints de grupo. Catalog.Collections
Grupo Nó da árvore da coleção. Declara fields tipados, sort e target. Grupos sempre listam em ordem alfabética. Catalog.Groups
Item Entrada de catálogo: nome, ano, fotos e value = estimativa de referência por unidade. Catalog.Items
Cópia Um exemplar físico, com condição, preço pago, estimativa própria opcional, data de aquisição, status e notas. coluna JSON Items.Copies
Version Contador de concorrência otimista do agregado inteiro. Viaja como ETag opaco; nunca como campo de DTO. Catalog.Collections.Version
Focal Ponto focal (x, y de 0 a 1) na linha da imagem. Um ponto serve todas as proporções; nunca reescreve os bytes. Storage.Images.FocalX/Y
Variant thumb (400 px), display (1400 px) ou full (original). Sempre nomeada pelo cliente. ?size= em /api/images/{id}
Store listing Checklist curado global, fora de qualquer tenant, que uma conta pode instanciar como coleção nova. Store.StoreListings
Archive Zip de backup: manifest.json + JSON das coleções + os bytes das imagens. Serve para exportar e reimportar. /api/export, /api/import

As invariantes que sustentam o resto

Se você só tem cinco minutos antes de mexer no código, leia estas. Cada uma tem um teste que falha quando é quebrada, e cada uma tem um modo de falha silencioso — o motivo de estarem escritas.

InvarianteO que acontece se quebrarDetalhe
Isolamento de tenant é do banco, não do serviço. Ninguém escreve WHERE TenantId = … à mão. Um filtro esquecido em uma query nova vaza dados entre contas sem erro nenhum. Tenancy
Escrita em coleção ou item exige If-Match; ausência é recusada com 428. Uma precondição opcional só protege o cliente que já lembrava de enviá-la — nunca o que está a ponto de apagar uma tarde de trabalho. Concorrência
Bytes de imagem vivem em IImageStore, um diretório por tenant; a linha no banco é só metadado. Blobs no banco tornam backup, cota e cópia por tenant impossíveis de oferecer honestamente. Imagens
Imagem só é destruída pelo coletor, e só depois da carência inteira. Apagar no momento da desreferência acopla destruição irreversível a um PUT de documento inteiro. Não há backup em lugar nenhum do sistema. Coletor
Qualquer coisa que produza texto localizado roda depois de UseRequestLocalization. O handler de exceção monta o título enquanto a exceção sobe: fora de ordem, responde em inglês para quem pediu português. Pipeline
Posse é derivada de copies; não existe flag owned. Um valor que o servidor calcula mas ignora na entrada dessincroniza em silêncio no round-trip GET → PUT. Itens
null significa algo em currency, sort, target, focal e copy.value. Resolver o null na escrita congela a herança: o dia em que o padrão da conta muda, a coleção não acompanha. Nulls
Nenhuma string visível ao usuário nasce em componente; nenhum valor visual nasce fora de _themes.scss. Uma string literal quebra a troca de idioma em runtime; um hex literal quebra 6 dos 7 temas — e só aparece nos escuros. Frontend

Estado atual e limites conhecidos

Nada abaixo é bug: são escolhas de v1 registradas como follow-up. Suporte precisa reconhecê-las porque cada uma tem um sintoma visível.

Fechados nesta rodada

Um grupo com itens pode ser apagado — o diálogo pergunta o destino do conteúdo, em vez de recusar. Um grupo pode ser movido para outro pai. A lista mostra os campos customizados do grupo, e a busca alcança tags, descrição e valores de campo. Vários itens podem ser editados de uma vez. O app funciona em tela de celular. Um Viewer não escreve mais. Uma falha de rede aparece.

LimiteSintoma para quem usaForma durável
Não há undo, exceto para apagar um item Apagar um item mostra Desfazer no toast; qualquer outra exclusão é definitiva. E até esse undo é guardado por versão: se alguém salvou a coleção nesse intervalo, a restauração é recusada e o item continua apagado Uma pilha de undo de verdade, ou uma lixeira
Um item restaurado perde a posição manual Volta ao fim do grupo. A ordem manual é o índice do array e nada persiste posição por item Nada barato — ver ADR sobre ordem manual
Cobrança não existe O cartão do plano diz isso, e a ação está desabilitada. Nada no app é limitado por plano hoje Entitlement no servidor, antes de qualquer paywall
Não há políticas de compartilhamento do tenant O acesso é a lista de membros mais o linkShare por coleção. As três chaves que sugeriam o contrário foram removidas porque não persistiam nada Campos reais no DTO do tenant, se e quando a regra existir
Papel é do tenant, não da coleção Um Editor escreve em qualquer coleção da conta, inclusive uma que não foi compartilhada com ele. CollectionMember.Role é exibido e não autoriza nada Checagem por coleção no serviço
A lista de itens não é virtualizada Uma coleção de 286 itens renderiza 286 linhas. Ainda responde; em milhares, não vai Virtualização na tabela, mais paginação no contrato — hoje GET /api/collections devolve o vault inteiro
Item.img continua no contrato e não serve para nada Nenhum. É preenchido pelo seeder, validado e devolvido, e nada busca nada com ele — fotos de verdade são photoIds. Até recentemente o nome do arquivo era impresso na tela onde devia haver uma foto Remover do DTO numa mudança de contrato deliberada
Não há página pública de coleção O interruptor de compartilhamento por link está desabilitado e diz isso. Antes ele afirmava que qualquer pessoa com o link podia ver a coleção, sem link algum para copiar e sem rota que servisse coleção nenhuma Rota anônima somente-leitura, URLs de imagem assinadas e meta OpenGraph — um link de vitrine que abre em branco não é compartilhável
Um convite não chega a ninguém Não há transporte de e-mail no repositório. O membro aparece na lista e não consegue entrar Convite com token de definição de senha, e um transporte
JWT em localStorage, 8 h, sem refresh token Sessão cai sem aviso depois de 8 h; um 401 no meio da sessão desloga Refresh token + cookie HttpOnly
Throttle de login com estado em memória Um deploy zera todos os contadores; com mais de uma instância, o limite é por nó Tabela Identity.LoginAttempts por (Kind, Key), deliberadamente não tenant-owned
Login enumera contas por tempo de resposta E-mail inexistente responde em microssegundos; e-mail válido paga PBKDF2 Hash-chamariz fixo, ao custo de todo palpite pagar PBKDF2
Sem índice em Email sozinho (IX_Users_TenantId_Email começa por TenantId) Todo login varre a tabela; o pré-portão em memória existe para a tentativa recusada nem chegar ao SQL Índice dedicado em Email
Concorrência tem granularidade de coleção Duas pessoas editando itens diferentes da mesma coleção: uma é recusada com 412 e precisa recarregar Não há onde guardar um token por item — recusar demais custa um reload, recusar de menos custa o trabalho
Seções dividem só os itens do próprio grupo Num grupo que tem sub-grupos e seções, os itens vindos dos sub-grupos aparecem na faixa “sem seção” no fim da lista Rotular cada faixa pelo rótulo mais específico que o item tem — a seção dele, ou o sub-grupo a que pertence
Membros de coleção são snapshots desnormalizados Renomear um membro no tenant não propaga para as coleções Referência ao usuário em vez de cópia
Membros convidados não conseguem entrar PasswordHash nulo e não existe fluxo de convite/definir senha Fluxo de convite com token
Imagens são servidas por URL de GUID não adivinhável, anônima Quem tem o link vê a foto, mesmo sem sessão URL assinada com validade
Governança de marca — pendente

O app usa a linguagem visual “Vault” do design de origem (acento indigo #5453C4, 7 temas trocáveis). O manual de marca Colecionary em docs/ define outra identidade (Vault Purple #7C5CFF, Colecionary Night #101827, dark-first). Nenhuma linguagem visual nova pode ser inventada fora desses dois sistemas. Reconciliar exige revisão formal de identidade; mecanicamente é uma mudança em um arquivo (styles/_themes.scss).
